# Chess Lab — My Games data package

Precomputed data for the **My Games** section on [Chess Lab](https://www.neilldata.com/chess-lab/).

These files are generated by `build_export.py`. They are **not** written into the `toxieon/chess-lab` repo; they are a data package the site can load. Do not invent or hand-edit engine evaluations — regenerate with the script.

`opening_explanations.json` sits next to the script and supplies the plain-English opening paragraphs. Leave it in place when you re-run.

## How to regenerate

```bash
python3 /workspace/chess/export/build_export.py
python3 /workspace/chess/export/build_export.py --months 2026-10,2026-11 --depth 16
python3 /workspace/chess/export/build_export.py --export-only   # rebuild JSON from the eval cache, no new engine searches
```

Requirements: Python 3 with `python-chess`, and the Stockfish binary at `/workspace/chess/stockfish`.

The script:

1. Fetches Chess.com monthly archives **serially** with a descriptive `User-Agent`. Past months are cached under `/workspace/chess/cache/games-YYYY-MM.json`. The current month is always refetched.
2. Analyses every position with Stockfish at `--depth` (default 16, MultiPV 3 on the player's turns). Evals are cached in `/workspace/chess/cache/evals.sqlite`, keyed by FEN (placement, side, castling, en passant), depth, MultiPV and engine name. Re-runs only search new positions.
3. Writes `games.json`, `puzzles.json`, `patterns.json` and `openings.json`.

Default months: October 2026 and November 2026. Add later months with `--months`.

## Eval conventions (all files)

Every engine score is from **Brandon's perspective**, never from White's, unless a field is explicitly named otherwise.

- `{"cp": 80}` — 0.80 pawns in Brandon's favour.
- `{"cp": -150}` — 1.50 pawns against him.
- `{"mate": 3}` — he mates in 3 moves.
- `{"mate": -2}` — he is mated in 2 moves.
- `{"mate": 0, "winner": "white"|"black"}` — the position is already checkmate. Use `eval_cp` for the sign: `+10000` if he delivered it, `-10000` if he was mated.

`eval_cp` is the same score as a signed integer for graphs (mates converted with a mate score of 10000). You can clip it in the UI (for example to ±1500) without changing the raw `eval` object.

**Nothing in these files is a guessed eval or a guessed line.** If a field is an evaluation or a PV, it came from Stockfish (or from the rules of chess, for an already-checkmate / already-drawn terminal position).

Judgements on his moves, using capped centipawn loss (cap 1500) versus the position after the move he played:

| judgment     | meaning |
|--------------|---------|
| `great`      | He played the engine's best move, and the second-best was ≥ 200cp worse. |
| `best`       | He played the best move, or loss ≤ 20cp. |
| `good`       | loss < 50cp |
| `inaccuracy` | 50–149cp |
| `mistake`    | 150–299cp |
| `blunder`    | ≥ 300cp |

Opponent moves have `judgment: null`.

## `games.json`

One object:

```
{
  "generated_melbourne": "ISO-8601 timestamp in Australia/Melbourne",
  "player": "brandonneillthegreat",
  "player_url": "https://www.chess.com/member/brandonneillthegreat",
  "months": ["2026-10", "2026-11"],
  "engine": {"name": "Stockfish 17.1", "depth": 16, "multipv": 3, "notes": "..."},
  "counts": {"games": 0, "puzzles": 0, "patterns": 0},
  "games": [ Game, ... ]
}
```

Games are sorted oldest to newest by start date.

### Game

| field | type | meaning |
|-------|------|---------|
| `id` | string | Chess.com live game id (the number at the end of the URL). |
| `url` | string | `https://www.chess.com/game/live/<id>` |
| `date` | string | Start time in Australia/Melbourne, ISO-8601 with offset (`+10:00` or `+11:00`). |
| `end_melbourne` | string | End time, same zone. |
| `colour` | `"white"` or `"black"` | Brandon's colour (Australian spelling). |
| `opponent` | string | Opponent's username. |
| `ratings` | `{player, opponent}` | Ratings at the time of the game. |
| `white`, `black`, `white_elo`, `black_elo` | | Both sides, for the board header. |
| `time_control` | string | Raw Chess.com value (`"60"` for 1+0, `"180+2"` for 3+2). |
| `time_control_label` | string | Display form (`"1+0"`). |
| `time_class` | string | `bullet` / `blitz` / `rapid` / `daily`. |
| `rated` | bool | |
| `result` | `"win"` / `"draw"` / `"loss"` | From Brandon's perspective. |
| `result_pgn` | string | `"1-0"`, `"0-1"`, `"1/2-1/2"`. |
| `termination` | string | Chess.com termination text (e.g. won on time, checkmate). |
| `pgn` | string | Full PGN, including clock comments and headers. Enough to replay the game on a board. |
| `opening` | object | `{eco, name, family, eco_url}`. `name` is a cleaned, readable opening name from the PGN `ECOUrl` / `ECO` tags (e.g. `Italian Game: Two Knights Defense`). `family` drops trailing move-list suffixes so the UI can group close variations. |
| `plies`, `my_moves` | int | |
| `best_move_count`, `best_move_pct`, `blunder_count`, `mistake_count`, `great_count` | | Quick stats for lists. |
| `moves` | array | One entry per ply, see below. |
| `engine` | object | Engine used for this game. |

### Move (each ply)

| field | type | meaning |
|-------|------|---------|
| `ply` | int | 1-based ply index. |
| `move_number` | int | Full-move number (both White's and Black's 12th move are `12`). |
| `san`, `uci` | string | The move that was played. |
| `colour` | `"white"` or `"black"` | Who played this ply. |
| `is_player_move` | bool | `true` if this is Brandon's move. |
| `fen_before`, `fen_after` | string | Standard FENs. Use `fen_after` (or the next row's `fen_before`) to place the pieces after the move. |
| `eval` | object | Stockfish eval of the position **after** this move, from Brandon's perspective (`cp` or `mate`). |
| `eval_cp` | int | Same eval as a signed integer, for the eval graph. Plot `eval_cp` against `ply`. |
| `eval_before` | object or null | Eval **before** this move (only set on his moves). |
| `best_san`, `best_uci` | string or null | Engine best move at `fen_before` (only on his moves). |
| `second_san` | string or null | Second-best move, when MultiPV found one. |
| `loss_cp` | int or null | Capped centipawn loss of the played move (his moves only). |
| `gap_cp` | int or null | Capped gap between best and second-best, for uniqueness / “great move” marks. |
| `judgment` | string or null | See table above. Use this to mark blunders, mistakes and great moves on the graph and the move list. |
| `depth` | int | Depth actually used for the after-move eval. |

To replay: load the PGN, or step through `moves[]` and apply each `uci` to a board starting from the standard start position. To jump to a ply, load `fen_after`.

## `puzzles.json`

Chess.com-style puzzles built only from **his** blunders and mistakes.

A position becomes a puzzle when all of the following hold:

- It is Brandon's turn, and he did **not** play the engine's best move.
- Centipawn loss ≥ 150, **or** he missed a forced mate.
- The best move is clearly better than the second-best (gap ≥ 150cp, or a strictly faster mate). This is so each puzzle has one right answer.
- The position was not already hopeless for him (eval ≤ −400cp, or he was already being mated), unless the best move would have saved him or he missed a mate of his own.

Each puzzle:

| field | type | meaning |
|-------|------|---------|
| `id` | string | Stable id: `p-<gameId>-<ply>`. |
| `source` | object | `{game_id, url, move_number, ply, colour, opponent, date}`. Link back to the game and the exact move. |
| `fen` | string | FEN **just before** the bad move (his side to move). Start the puzzle from this position. |
| `side_to_move` | `"white"` or `"black"` | Always Brandon's colour for that game. |
| `played` | `{san, uci}` | The move he actually played (the wrong answer). |
| `solution` | `{san, uci}` | The engine's best move, then a short continuation from the same PV (up to 8 plies, alternating him and the opponent). Both SAN (for hints / move lists) and UCI (for a board component) are included. |
| `eval_before`, `eval_after` | object | Eval of the puzzle position, and of the position after his actual (bad) move. Same `cp` / `mate` convention. |
| `eval_best` | object | Eval of the engine's best move from the puzzle position. |
| `loss_cp`, `gap_cp` | int | Why it qualified. |
| `theme` | string | One of: `hanging-queen`, `mate-in-1`, `missed-mate`, `fork`, `f2/f7-weakness`, `back-rank`, `trapped-piece`, `loose-piece`, `king-safety`, `knight-to-h4`, `missed-tactic`. |
| `hint` | string | One-line hint for the puzzle UI. It points at the idea, not the exact square. |
| `goal` | string, optional | Short prompt, such as `Win the rook` or `Mate in 1`. Shown in place of `hint` when present. |
| `mate_in` | int or null, optional | Moves until mate when the line is a forced mate. Null or absent on material puzzles. |
| `depth` | int | Stockfish depth used. |

Suggested UI: show the `fen` on a board, his colour to move, `goal` when it is set and otherwise the hint, and accept the first UCI/SAN in `solution` as the correct first move. Then auto-play or let him play the rest of `solution`. After a fail, show `played` vs `solution`.

## `patterns.json`

Groups the puzzles by `theme` so the site can show repeated mistakes.

```
{
  "generated_melbourne": "...",
  "player": "brandonneillthegreat",
  "count": 0,
  "recurring_count": 0,
  "patterns": [ Pattern, ... ]
}
```

| field | type | meaning |
|-------|------|---------|
| `id` | string | `pattern-<theme>`. |
| `theme` | string | Matches `puzzles[].theme`. |
| `title` | string | Short human title, e.g. `Queen left hanging`. |
| `description` | string | Plain-English explanation of the habit, suitable to show on the page. |
| `count` | int | Number of puzzles in this pattern. |
| `recurring` | bool | `true` when `count >= 2` (the ones worth calling out as a habit). |
| `puzzle_ids` | string[] | Ids into `puzzles.json`, in game/move order. |

Highlight patterns where `recurring` is true. Expected recurrences from earlier recaps include queens left hanging, missed mates in one, f2/f7 left weak (including Qxf2#), and a knight sent to h4/h5 that then costs material.

## `openings.json`

His openings as White and as Black, with proper names.

```
{
  "generated_melbourne": "...",
  "player": "brandonneillthegreat",
  "as_white": [ Opening, ... ],
  "as_black": [ Opening, ... ]
}
```

Each list is sorted by number of games, descending.

| field | type | meaning |
|-------|------|---------|
| `name` | string | Family name, e.g. `Italian Game` or `Queen's Pawn Opening: Zukertort Variation`. |
| `variation` | string or null | The most common full Chess.com variation name if it is more specific than `name`. |
| `eco` | string | Most common ECO code in the group (e.g. `C50`, `A04`). |
| `eco_url` | string | Chess.com openings URL for the most common variation. |
| `colour` | `"white"` or `"black"` | |
| `moves` | string | The move sequence he usually plays in this opening, in SAN (`1.Nf3 d5 2.g3 Nf6 …`). Chosen as the longest prefix that still covers a good share of the games. |
| `games`, `win`, `draw`, `loss` | int | |
| `score_pct` | number | `(wins + 0.5 * draws) / games * 100`. |
| `example_games` | array | Up to 5 examples: `{id, url, result, date}`. Prefer a mix of results, newest first. Use these as “click to replay” links into `games.json`. |
| `explanation` | string | One paragraph, plain English, of what the opening actually is. Safe to show under the name. |
| `variations` | array | Finer Chess.com variation names inside this family, each with `name`, `eco`, `games`, `win`, `draw`, `loss`, `score_pct`, `moves`. Useful if you want a second level in the UI. |

Names are cleaned from the PGN `ECOUrl` slug: hyphens become spaces, Réti / King's / Queen's / Van't Kruijs / Petrov's and similar are restored, and a colon is inserted after the family (`Italian Game: Two Knights Defense`).

## Suggested UI wiring

- **Game list + replay + eval graph:** `games.json`. Plot `moves[].eval_cp` (clip if you like). Colour or mark plies where `judgment` is `blunder`, `mistake`, or `great`. A click on a blunder can jump to the matching puzzle (`p-<id>-<ply>`).
- **Puzzles tab:** `puzzles.json`, optionally filtered by `theme` from `patterns.json`.
- **Habits / “you keep doing this”:** `patterns.json` where `recurring` is true, with a board for each linked puzzle.
- **Openings tab:** `openings.json`, split into As White / As Black, showing the real name, the usual moves, W–D–L, and the explanation paragraph. Example-game links open the replay view.

## Cache layout (not part of the site package)

- `/workspace/chess/cache/games-YYYY-MM.json` — raw Chess.com monthly archives.
- `/workspace/chess/cache/evals.sqlite` — Stockfish results, so a later run with new November (or December) games only analyses the new positions.

The Chess.com PubAPI must be requested **one URL at a time** with a `User-Agent`. Do not parallelise those fetches.
